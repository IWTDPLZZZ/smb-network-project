# SMB Network Lab

Лабораторная работа по проектированию и настройке сетевой инфраструктуры малого и среднего бизнеса (SMB) в **Cisco Packet Tracer**.

В проекте реализована **отказоустойчивая топология маршрутизации** с использованием **VLAN**, **HSRP** (резервирование шлюза), **EIGRP** (динамическая маршрутизация), **ACL** (списки контроля доступа) и **Port Security** на оборудовании Cisco.

Файл топологии: [`first_project.pkt`](./first_project.pkt) (Packet Tracer 9.0).

---

## Краткое описание

Лаборатория моделирует корпоративную сеть из двух логических зон:

| Зона | Цвет на схеме | Роль |
|------|---------------|------|
| **Синяя** | RGB(0, 0, 255) | Центральный сегмент: пользователи, серверные ресурсы, пограничный маршрутизатор |
| **Жёлтая** | RGB(255, 210, 12) | Удалённый/филиальный сегмент с резервированием шлюза (HSRP) |

Зоны связаны через два независимых линка `/30`, что обеспечивает путь к филиалу даже при отказе одного из маршрутизаторов жёлтой зоны.

---

## Используемые технологии

- **VLAN** — сегментация L2 (native, users, servers)
- **Router-on-a-Stick (802.1Q)** — маршрутизация между VLAN через sub-interfaces
- **HSRP** — виртуальный шлюз по умолчанию для хостов жёлтой зоны
- **EIGRP (AS 10)** — динамическая маршрутизация между Router0 / Router1 / Router2
- **ACL (extended)** — ограничение доступа филиала к серверу (только HTTP)
- **Port Security** — защита access-портов коммутатора (sticky MAC, violation `restrict`)
- **DHCP + ip helper-address** — централизованная выдача адресов клиентам синей зоны
- **PVST** — spanning-tree на коммутаторах Catalyst 2960

## Структура зон

### Синяя зона (HQ / Core)

Устройства:

| Устройство | Модель | Назначение |
|------------|--------|------------|
| **Router0** | Cisco 2911 | Центральный маршрутизатор, inter-VLAN routing, ACL, EIGRP |
| **SW1**, **SW2** | Catalyst 2960-24TT | Access/trunk коммутация пользователей и сервера |
| **PC0** | PC-PT | Клиент users VLAN (DHCP) |
| **Server0** | Server-PT | DHCP + HTTP-сервер (`192.168.20.10`) |

Ключевые сети:

| VLAN | Имя | Подсеть | Шлюз |
|------|-----|---------|------|
| 2 | `nativeVlan` | `192.168.2.0/24` | `192.168.2.1` |
| 10 | `usersVlan` | `192.168.10.0/24` | `192.168.10.1` |
| 20 | `serverVlan` | `192.168.20.0/24` | `192.168.20.1` |

На Router0:

- Sub-interfaces `Gi0/0.2`, `Gi0/0.10`, `Gi0/0.20` (dot1Q)
- `ip helper-address 192.168.20.10` на VLAN 10
- Loopback `8.8.8.8/32` (эмуляция внешнего/служебного адреса)
- Extended ACL `PROTECT_SERVER` на `Gi0/0.20 out`

### Жёлтая зона (Branch / Redundant Edge)

Устройства:

| Устройство | Модель | Назначение |
|------------|--------|------------|
| **Router1** | Cisco 2911 | Active HSRP (priority **110**, preempt) |
| **Router2** | Cisco 2911 | Standby HSRP (preempt) |
| **Switch2** | Catalyst 2960-24TT | Access для ПК + Port Security |
| **PC1**, **PC2** | PC-PT | Клиенты филиала |

Сеть пользователей филиала:

| Параметр | Значение |
|----------|----------|
| Подсеть | `192.168.30.0/24` |
| Virtual IP (HSRP group 1) | `192.168.30.1` |
| Router1 | `192.168.30.2` (active) |
| Router2 | `192.168.30.3` (standby) |
| PC1 | `192.168.30.10`, GW `192.168.30.1` |

Port Security на Switch2 (`Fa0/3`, `Fa0/4`):

- режим access, VLAN 10
- sticky MAC-адреса
- violation: `restrict`

## Межзонная связность и EIGRP

| Линк | Подсеть | Интерфейсы |
|------|---------|------------|
| Router0 ↔ Router1 | `10.10.1.0/30` | `Gi0/1` ↔ `Gi0/0` |
| Router0 ↔ Router2 | `10.10.1.4/30` | `Gi0/2` ↔ `Gi0/0` |

На всех трёх маршрутизаторах поднят **`router eigrp 10`**.  
Клиентские sub-interfaces объявлены как `passive-interface`, чтобы не слать hello в сторону хостов.

Отказоустойчивость:

1. При падении **Router1** HSRP переводит VIP `192.168.30.1` на **Router2**.
2. EIGRP пересчитывает маршруты через оставшийся линк `10.10.1.4/30`.
3. Хосты филиала продолжают работать через тот же шлюз по умолчанию.

## Политика безопасности (ACL)

На Router0 применён список:

```text
ip access-list extended PROTECT_SERVER
 permit tcp 192.168.30.0 0.0.0.255 host 192.168.20.10 eq www
 deny   ip  192.168.30.0 0.0.0.255 host 192.168.20.10
 permit ip any any
```

Смысл политики:

- из жёлтой зоны к серверу `192.168.20.10` разрешён только **HTTP (www)**;
- любой другой IP-трафик к серверу из филиала **запрещён**;
- остальной трафик сети не блокируется.

Дополнительно на access-портах Switch2 включён **Port Security**, чтобы ограничить подключение посторонних MAC-адресов.

```text
                 ┌──────────────── СИНЯЯ ЗОНА ────────────────┐
                 │                                            │
   PC0 ── SW1 ── SW2 ── Server0(192.168.20.10)                │
                 │                                            │
                 └────────────── Router0 ─────────────────────┘
                         /              \
                 10.10.1.0/30        10.10.1.4/30
                       /                    \
               Router1 (Active)        Router2 (Standby)
               192.168.30.2            192.168.30.3
                       \                    /
                        \── VIP 192.168.30.1 ──/
                                   │
                                Switch2
                               /        \
                             PC1        PC2
                 └────────────── ЖЁЛТАЯ ЗОНА ──────────────┘
```

## Как открыть лабораторию

1. Установите [Cisco Packet Tracer](https://www.netacad.com/cisco-packet-tracer) (рекомендуется версия 9.x).
2. Откройте файл `first_project.pkt`.
3. Проверьте связность:
   - `PC0` получает адрес по DHCP из пула `192.168.10.100–199`;
   - `PC1` ходит на `http://192.168.20.10` (разрешено ACL);
   - отключение Router1 не должно «ронять» шлюз филиала (HSRP failover).

## Цели лабораторной работы

- Сегментировать сеть с помощью VLAN и trunk/access портов
- Организовать маршрутизацию между сегментами (RoAS)
- Обеспечить отказоустойчивый шлюз филиала через HSRP
- Построить динамическую маршрутизацию EIGRP между площадками
- Ограничить доступ к серверным ресурсам списками ACL
- Защитить порты коммутатора механизмом Port Security

---

## Лицензия / использование

Учебный проект. Конфигурации предназначены для демонстрации в Cisco Packet Tracer и не являются production-ready шаблоном без доработки (пароли, AAA, шифрование служебного трафика и т.д.).
